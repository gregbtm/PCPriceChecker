## How the app and n8n talk
1. Push: the app POSTs JSON to an n8n Webhook node for every alert (my setting "n8n (webhook)" on the dashboard's Integrations tab, `webhook_url`, plus an optional header `X-PCPC-Token`). Payload fields: event (price_alert | options | price_drop | restock | scrape_failure | daily_summary | test), ts, type, componentName, price, currency, retailer, alertThreshold, url, message. Use the PRODUCTION webhook URL (not /webhook-test/) once a workflow is active.
2. Pull: n8n calls the app's read-only API with HTTP Request nodes: GET /api/health (scrapers.failing = sources failing 3+ times in a row, scrapers.sources[].status), GET /api/alerts (one item per component at or below its alert price), GET /api/components/<id>/offers (current qualifying offers), GET /api/scrape-runs?limit=50, GET /api/integrations.
The app never reads or writes n8n's database, and you must not either.
